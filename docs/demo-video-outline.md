# 演示视频大纲

2026-11-03，对应板上最终版 feat/st-fmax 1ec0721（Flash 里就是这一版）。数字的出处见文末。

建议总长 6–8 分钟：一半时间放实机画面，一半讲设计。下面每节标了建议时长和要拍的画面。

## 0. 开场（约 20 s）

- 一句话说明：Ti60F225 上的实时风格迁移，摄像头进、HDMI 出，3 种风格按键切换。
- 画面：板子、摄像头、显示器全景；上电后从 Flash 启动，几秒内出图。

## 1. 实机功能演示（约 2 min，最重要）

依次拍：

1. **分屏**：左边原图，右边风格化结果。左上角 OSD 显示实时帧率 FPS 16–17。
2. **切风格**：KEY2 把光标移到 STY 行，KEY3 依次切 bright → gouache → comic。切换在下一帧生效，不重新配置、不丢帧。
3. **全屏**：KEY2 回到视图行，KEY3 在 SPLIT / FULL 之间切换。
4. **动态场景**：手在镜头前移动，或摇一下摄像头，说明是实时处理。
5. **自动曝光**：开关灯或遮挡镜头，亮度自动恢复。
6. **白平衡**：
   - 自动模式（OSD 显示 `WB AUTO`）；
   - 白纸占满画面，短按 KEY0，OSD 从 `WB CAL` 变成 `WB LOCK`；
   - 再把手或彩色物体放进画面，颜色不漂；
   - 长按 KEY0 约 1 秒回到 `WB AUTO`。

拍的时候注意：显示器的反光，和摄像头对着显示器时出现的循环画面。

## 2. 系统数据链路（约 1.5 min）

要讲清楚一帧数据从摄像头到 HDMI 走了哪些模块。下面这张图可以直接画成 PPT：

```
SC431HAI 摄像头 ──MIPI CSI-2 4-lane，RAW10 1280×720（2×2 binning）
   │
CSI-2 RX（厂商 IP）→ csi_capture → 异步 FIFO → line_release              [CSI 50 MHz → sys_clk 125 MHz]
   │
ISP：黑电平/白平衡增益 → 去马赛克 → gamma → 饱和度 → RGB565 抖动
   │   └─ 原始统计 + 灰像素统计 ──APB──► RISC-V（AE/AWB）──┬─ 写回 ISP 增益
   │                                                        └─ I2C 改传感器曝光
   ▼
DDR3「ISP 帧环」（4 槽，RGB565）
   │
风格迁移加速器（sys_clk 125 MHz）
   st_pre：1280×720 → 2×2 平均 → 640×360
   13 个 pass：每个 pass 从 DDR 读一个张量 → DW 3×3 → PW 1×1（可带 LN / FiLM / 残差）→ 写回 DDR
   st_post：2×2 复制回 1280×720 + RGB565 抖动
   ▼
DDR3「PROC 帧环」
   │
合成器：原图层 + 结果层，分屏/全屏，OSD 叠加                              [像素时钟 148.5 MHz]
   │
DVI/HDMI 编码 → 1080p60（1280×720 画面居中）
```

要点：

- **三种存储各管一段**：
  - 帧和中间特征图放 DDR，加速器每帧约 49 MB；
  - 网络权重和 3 个风格的参数全部常驻片上 ROM，推理时不从 DDR 读权重；
  - 片上 RAM 只放几行的行缓存。
- **采集、处理、显示三者解耦**：帧环不要求它们同步，所以摄像头约 22 fps、网络约 17 fps、显示 60 fps 能各跑各的。
- **DDR 仲裁**：显示读的优先级最高，加速器最低。这样计算再忙也不会让画面闪。（这是调过的坑，见第 6 节。）
- **时钟**：
  - sys_clk 125 MHz：加速器、ISP、SoC；
  - DDR 控制器内核 100 MHz；
  - CSI 50 MHz；
  - 像素 148.5 MHz。
- **RISC-V（Sapphire）的工作**：
  - 上电时通过 I2C 配置摄像头；
  - 轮询按键，写菜单寄存器（风格、视图）；
  - 每帧跑一次 AE/AWB。

## 3. 网络设计（约 1.5 min）

- **结构**（画结构图，见 docs/st-network-architecture.md §2.1）：`tiny_dw_guided`，三级分辨率。
  - 主干：160×90，80 通道，深度可分离卷积，残差，LayerNorm。
  - H/2 分支：320×180，带 FiLM 全局调制（GAP → 小 MLP → 每通道的 γ、β）。
  - 全分辨率 guide 分支：640×360，只有 3→8 和 8→3 两层，用来补细节。
  - 计算量 62% 在 H/4。
- **为什么这么设计**：
  - 高分辨率部分极便宜，计算集中在低分辨率的主干；
  - 用 LN 代替 IN，可以流式计算；
  - FiLM 用 GAP 得到全局信息，GAP 在写 DDR 时顺路累加，不用多读一遍。
- **规模**：
  - 参数 33,569（3 个风格；共享 29,171，每个风格 1,466）；
  - 部署后约 39 KB，远低于 500 KB 的要求；
  - 计算量 0.59 GMAC/帧。
- **训练**：
  - 以 White-box Cartoonization 为教师做蒸馏；
  - 先训宽网络，按通道重要性剪枝到 90% 档，再微调；
  - 最终版 s3d 额外修正了输出偏黄。
- **多风格**：
  - 卷积全部共享，每个风格只换"风格包"：LN 的 γ/β、FiLM MLP、guide 仿射；
  - 仿射系数为正，折进卷积后 int8 权重码不变，所以每多一个风格几乎不多占硬件。
- **量化**：
  - W8A8，3 个风格联合校准；
  - LN 的 1/√D 用查表，FiLM 用整数 MAC，不需要除法器。

## 4. 加速器硬件（约 1.5 min）

- **方案选择**：先试过全片上流式，结论是放不下，瓶颈是片上存储而不是 DSP。
  - 全流式估算约 1.2 MB；
  - Ti60 整片 RAM 约 320 KB。
  - 所以改成 DDR 多 pass 的块引擎。
- **引擎组成**：
  - PW 阵列 8×16 = 128 MAC/周期（64 个 DSP）；
  - DW 3×3（也负责普通 3×3 卷积的 im2col）；
  - LN/FiLM 单元、残差相加；
  - 读写 DMA、AXI 仲裁。
- **性能**：
  - 125 MHz，每帧约 7.4M 周期，约 59.6 ms，**板上 16.8–17.4 fps**；
  - 3 个风格帧率相同。
  - 主干 PW 的 pass 达到 127.5 MAC/周期，接近满载。
- **资源**（放资源表截图）：
  - XLR 60,191/60,800（99.0%），RAM10 256/256（100%），DSP 159/160；
  - sys_clk 最高 139.7 MHz，时序满足。
  - 可以强调"三种资源都几乎用满"，以及为此做了哪些压缩（第 6 节）。
- **验证方法**：
  - 每个数值定义先在 Python golden 里实现并测精度，再写 RTL；
  - RTL 和 golden 逐位一致，整引擎仿真跑完整 13 个 pass、3 个风格；
  - 上板后用 UART 遥测读帧数、错误数和周期数。

## 5. 画质和对比（约 1 min）

- **硬件对 fp32 的保真度**（6 张测试图）：bright 37.3–40.9 dB，gouache 35.8–38.7 dB，comic 32.7–37.3 dB。
  - 和训练端的整数推理一致，说明硬件化没有额外损失。
- **对教师网络**（单风格 prune90 版本，板上完整通路）：30.2 dB / SSIM 0.908。
- **和标准网络对比**（表格见 docs/st-network-architecture.md §1）：
  - 简化版 CycleGAN（ResNet-6）参数 7.8M、123 GMAC，本网络少约 230 倍参数、208 倍计算量；
  - 它在 Ti60 上放不下，按同一引擎的峰值折算 ≥ 7.7 s/帧；
  - CPU（Ryzen 9 5900X 单线程）上本网络 26.8 ms，CycleGAN-R6 2695 ms。
- **画面**：原图和 3 种风格的四宫格对比。可以用 `st_work/g360` 的测试图，也可以直接截板上画面。

## 6. 难点和经验（约 1 min，挑 3–4 条）

- **片上 RAM 一块块抠出来**：
  - Efinity 会把数组深度向上取到 2 的幂，所以拆成 2 的幂深度的数组；
  - 小 FIFO 改用 SRL；
  - 用 tag 代替数据存进 FIFO。
  - 最终刚好 256/256。
- **仿真全过、上板才出的 bug**：
  - 输出色调随时间循环变化：GAP 的清零脉冲丢了，统计跨帧累加。之后有状态的模块都至少连续测 3 帧。
  - RAM 没按 Efinity 的推断模板写，仿真对、综合错，上板黑屏。
- **视频通路**：
  - 画面左边有一条竖带显示的是右边的内容：FIFO 跨帧残留 1 个 beat；
  - 分屏闪烁：加速器在 DDR 仲裁里抢走了显示带宽。
- **偏色排查**：分别看相机输入、FPGA 输出和 fp32 推理，确认 FPGA 输出等于 fp32，偏黄来自模型本身。于是分两头处理：模型偏黄在训练端修，相机偏暖用固件 AWB 修。

## 7. 结尾（约 15 s）

- 汇总：16.8+ fps、3 风格实时切换、39 KB 模型、资源 99%，权重全部片上。
- 展望：
  - 720p30 需要更多 DSP 或更窄的网络；
  - 白平衡加色彩校正矩阵（CCM）；
  - 更多风格（需要先把 OCR 缩小腾出 RAM）。

## 和赛题要求的对应（讲之前自己核对，别讲过头）

| 要求 | 现状 | 怎么讲 |
|---|---|---|
| 摄像头采集到 DDR，乒乓缓存 | 1280×720 写入 4 槽帧环，比乒乓更宽松 | 直接讲 |
| 神经网络加速器：3×3 卷积、ReLU、归一化的硬件近似、AXI4 读写 DDR | 都有；归一化是 LN 的整数实现 | 直接讲 |
| HDMI 720p60 或 1080p30 | 输出 1080p60 | 直接讲 |
| 原图和结果并排、屏上显示 FPS | SPLIT 模式 + OSD 帧率 | 直接讲 |
| 640×480 下稳定 ≥ 15 fps | 网络在 640×360 上跑（从 1280×720 下采样，16:9），16.8–17.4 fps | 说明分辨率选 16:9 是为了和摄像头、显示一致，像素数是 640×480 的 75% |
| RISC-V C 驱动（摄像头、加载权重、启动/等待/中断） | 摄像头配置、按键、AE/AWB 在固件里；**加速器由硬件按帧自动启动，权重在片上 ROM，固件不加载权重，也没用中断** | 如实说明是"硬件自主调度"，别说固件驱动了加速器 |
| ≥ 2 个风格按键切换、< 100 ms、不丢帧 | 3 个风格，下一帧开始生效（最长约 1 帧等待 + 1 帧处理），不重新配置 | 别给具体毫秒数，或说"下一帧生效" |
| 1280×720@30 fps 处理 | 没做到：输出是 1280×720，但网络在 640×360 上跑，约 17 fps | 放在展望里，不要声称达到 |
| 参数 < 500 KB，并和标准网络比 PSNR/SSIM、延迟 | 约 39 KB；参数量、计算量、延迟都比了；**CycleGAN 没有训练，所以没有它的 PSNR** | 只比参数、计算量和延迟；PSNR 说的是对教师的 PSNR |
| 创意交互 | 白纸一键标定白平衡 + 自动曝光，算不上很强的创意 | 可以当亮点之一提，不要夸大 |
