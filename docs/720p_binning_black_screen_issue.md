# 720p binning 改造排查记录

| 项 | 值 |
|---|---|
| 板卡 | Titanium Ti60F225 + SC431HAI (4-lane) + DDR3 |
| 起点 | `edd33d9`（1080p 裁切，画面正常） |
| 中间基线 | `6ee2b1a`（1280×720 中心裁切） |
| 当前 | 1280×720 2×2 binning，约 22 fps，颜色与几何均正常，居中显示在 1080p 光栅内 |
| 日期 | 2026-10-20 |

## 1. 问题与根因（按出现顺序）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 黑屏，HDMI 锁定 | `frame_buffer_read.sv` 里 `LAYER_X/LAYER_Y` 重复声明，综合器丢弃了新声明（`VERI-2170/1329`），实际 `layer_x = 960`，窗口永远不命中 | 删除旧声明；`build_all.sh` 遇到这两条警告直接失败 |
| 2 | 定格、左右两份、摇晃 | 厂商 720p 表写 `0x3018=0x3A/0x3019=0x0C`（2-lane）；删掉后传感器只发 FS/FE 短包、没有行数据。DDR 从未被写，读侧显示的是上次运行的残留 | 不写 `0x3018/0x3019`（上电默认 4-lane） |
| 3 | 块状错位、左侧异色竖条、曝光跳动 | 把厂商 binning 表的 PLL 整组换成 1080p 值，或在 1080p 表上只加 binning 开关：binning 的数字水平合并（`0x5000/0x5900/0x5901`）与不配套的时钟 / 模拟时序 / HTS 组合 | 整套保留厂商 binning 的 PLL 与模拟时序，只改 lane 差异 `0x301F=0x10`、`0x36EC=0x65` |
| 4 | 灰色画面，红绿行条纹，每帧 540 行 | HTS 1500 时 4-lane 下 MIPI 每行发送时间不够，传感器每 4 行丢 1 行，行奇偶错乱 | HTS 1500 → 2048 |
| 5 | 颜色很淡，发灰 | 曝光不足（厂商曝光按 112 fps 设定），且 8 位黑电平约 16 未扣除，gamma 后变成整体灰雾 | 曝光 40 ms + 模拟增益约 2x；FPGA 在 debayer 前扣黑电平并拉伸；`WB_G` 按灰度世界改为 0.52 |
| 6 | 竖边锯齿、边缘红蓝色边 | 采集侧打包 `{p3,p2,p1,p0}` 与下游"高半字先出、高字节在左"的约定相反，显示顺序为 `p1 p0 p3 p2`。CFA 相位此前恰好按错序选定，所以颜色看起来正常 | 打包改为 `{p0,p1,p2,p3}`；水平 CFA 相位随之翻转，用 `0x3211 0x02→0x03` 移回 |

#6 与 binning 无关，1080p 和裁切模式里也一直存在。

## 2. 关键判断依据

- **FPGA 读写通路**：`DBG_PATTERN=1` 把像素换成逐帧变基址的计数器（保留传感器的 vs/hs/de），
  在 `layer_fetch` 入口和出口各校验：每帧 460800 字、连续无断点、无欠载、无旧帧残留。
  它验证的是字的顺序，验证不了字内像素的排列，所以 #6 没被它发现。
- **镜像实验**：开关 `0x3221` 时场景翻转而错位纹路不动，说明 #3 的纹路产生在传感器镜像之后的数字后端。
- **二分**：在 1080p 基表上只加 `0x3215/0x3220` 画面干净、变亮、纵向压缩（只做了行合并）；
  再加 `0x5000/0x5900/0x5901` 才出现块状错位。
- **兄弟传感器**：Rockchip `sc450ai.c` 的 4-lane 与 2-lane binning 表只差 lane / MIPI 寄存器，
  binning 与模拟时序完全一致，所以只改 lane 差异是对的方向。
- **原始统计**：读侧探针给出四个 CFA 通道的均值、min/max、饱和与近黑比例，
  #5 的曝光、黑电平与白平衡都按它来定；#6 修改后用它确认 G 通道位置不变。

## 3. 寄存器含义（数据手册未记录，由多个 SmartSens 驱动对比推断）

| 寄存器 | 推断作用 | 全分辨率 | binning |
|---|---|---|---|
| `0x3215` | 行步进（奇 `[7:4]` / 偶 `[3:0]`） | `0x11` | `0x31` |
| `0x3220` | 读出模式，bit0 疑似垂直模拟合并 | — | `0x01` |
| `0x5000` | 数字模块使能，bit6 疑似数字合并 | `0x06` | `0x46` |
| `0x5900` | 数字水平合并，低 4 位 1 = 平均、2 = 求和 | — | `0x01` |
| `0x5901` | 未知，binning 表中恒为 `0x04` | — | `0x04` |

`0x3221` 只有 mirror `[2:1]` 和 flip `[6:5]`（数据手册表 2-11），不是 binning 开关。

| 开关 / 字段 | 位置 | 作用 |

| `frame_pix_num` | 遥测字节 18[7:4]、24[7:4]、27 | 每帧采集拍数低 16 位；1280×720 = `0x8400` |

摄像头模式（ST 关闭、`DBG_PATTERN=0`）下 `board_smoke_test.py --json` 字段对应：
`cap_samples` = `{sum[偶行高字节], sum[偶行低字节]}`，`cap_tiles` = `{sum[奇行高字节], sum[奇行低字节]}`

## 5. 未决

- 帧率约 22 fps。回到 30 fps 需要 VTS 约 2048，曝光相应降到 30 ms 以内。
- 曝光、增益、白平衡都是固定值，场景亮度变化大时需要自动曝光（固件经 APB 读统计值是一条可行路线）。
- debayer 是双线性插值，细节处仍会有轻微彩色噪点。
- `board_smoke_test.py` 的 `ok` 判定仍按 ST 开启时的条件写，ST 关闭时恒为 FAIL。

## 6. 视频重构 Phase 1 上板结论（2026-10-21）

自检路径（vid_testgen → vdma_wr → 测试环 → vdma_rd → vid_testchk）与旧帧缓冲共用 DDR 时，
约 8% 的自检帧夹带旧帧缓冲的 RAW8 数据，旧画面底部也偶有横向故障纹。

| 实验 | 结果 |
|---|---|
| 读响应改为按发出顺序回路由、下游统一 ID 0 | 不变 |
| 监视旧写入器每个突发的 W 拍数 | 全部正确 |
| 监视旧引擎在握手前撤回 AR/AW | 0 次 |
| 每方向最多 1 个未完成事务 | **0 错（1412 帧）** |
| 写 8 个、读 1 个未完成 | **0 错（1412 帧）** |

结论：板上的（加密）DDR 控制器在**多个读事务未完成**时返回错误数据；写可以流水。
`vid_subsystem` 的 `DDR_MAX_RD` 默认 1。仿真模型不复现这一行为（它按 AXI 规范工作）。

## 7. Phase 2a：新显示路径（2026-10-21）

图样帧（vid_patgen）→ vdma_wr → ISP 环 → vdma_rd（双时钟）→ compositor（148.5 MHz，每拍 1 像素）→ HDMI。
仿真里每个输出像素与 `pat_pixel()` 逐一比对一致。

上板首版显示读只有 30 帧/秒、约一半启动迟到、画面闪烁和撕裂。测得 DDR 读延迟通常 32 拍、
最大 1108 拍；关掉旧帧缓冲的 DDR 访问不变。把**写也限制为 1 个未完成**后，读延迟最大 597 拍，
显示读 60 帧/秒、迟到 0、合成器坏行不再增长。结论：控制器先服务已排队的写，再服务读。
`DDR_MAX_WR = DDR_MAX_RD = 1` 为默认值。

## 8. Phase 2b：ISP 前置（2026-10-21）

CSI（50 MHz，每拍 4 像素）→ `csi_capture` → 异步 FIFO + `line_release`（整行放行）→
`isp_top`（core_clk，每拍 2 像素：黑电平+白平衡 → 双线性去马赛克 → gamma → 饱和度 → 2×2 抖动 → RGB565）
→ `vdma_wr` → ISP 环 → 显示路径（同 Phase 2a）。ISP 的算术以 `sim/ref/isp_ref.py` 为规格，
`tb_isp` 把环里的帧与它逐像素比对（完整 ISP、全旁路、采集侧测试图三种），三种都逐位一致。

| 检查 | 结果 |
|---|---|
| 板上 `CSI_PATTERN=1`（传感器时序 + 固定图） | 帧签名 `0xa4f003e6`，与模型预测一致：CSI→ISP→DDR 逐位正确 |
| 原始统计（摄像头） | (0,0)/(1,1) 均值约 349，另两个约 206/257：G 在对角，与 `cfa_r = 2'b10`（GB/RG）一致 |
| 资源 | u_vid 0 DSP、38 块 Memory（ISP 7 块：行缓冲 4、gamma 3）；全片 DSP 4、Memory 164/256 |
| 时序 | core_clk slack 2.99 ns，pclk 13.4 ns |

首版上板 ISP 只写进约 8/22 帧，写侧 FIFO 溢出。原因在两个 DMA 引擎：FIFO 按 32 位字存，
AXI 侧每拍要凑 4 个字，W/R 通道**每 4 个时钟才走一拍**，一个 128 拍突发占住 DDR 端口约 512 个时钟，
读延迟峰值 596 就是这么来的。改为在 FIFO 之前打包成整拍（`vdma_wr`）、FIFO 之后再拆字（`vdma_rd`），
FIFO 存整拍，AXI 每时钟一拍：ISP 写入 474/474 帧、0 错，读延迟峰值降到 237，显示坏行不再增加。
代价是 FIFO 变宽（RAM 最宽 20 位，130 位要 7 块），每个引擎 4 → 7 块。

遥测按页轮换（字节 19 的 seq 低 2 位）：0 显示、1 摄像头路径、2 原始统计、3 DMA 自检，
`board_smoke_test.py --vid` 解码。

待看画面：颜色（红蓝是否对调，`cfa_r` 只能靠眼睛确认）、与 `ac6b658` 对比画质、灰度渐变是否还闪。

## 9. Phase 3：占位处理单元 + PROC 环 + 分屏（2026-10-21）

`proc_engine`：从 ISP 环按 NEW_ONLY 读每个新帧 → `proc_stub`（PASS / INVERT）→ 写 PROC 环，结果帧带源帧的 `src_seq`。
真实加速器以后替换 `proc_stub`，端口不变（带 sof/eol 的弹性流）。ISP 环 4 槽 2 个消费者（显示层 0、处理单元），PROC 环 3 槽。

合成器两层：`COMP_SINGLE`（单层）或 `COMP_SPLIT`（分屏列左边层 0、右边层 1），分屏列任意（不必 8 的倍数）。
每层只读能显示出来的列（`crop_beats()`：左层读到分屏列向上取整到 8 像素，右层从向下取整处开始），
所以分屏的 DDR 读量和单层一样。仿真 `tb_disp_split`（列 643）与 `tb_disp_split0`（列 0，层 0 不读）逐像素核对。

板上（顶层 `VID_SPLIT = 1`，列 640，右半反色），满负载：摄像头写、两层显示读、处理读写、DMA 自检同时运行：

| 项 | 结果 |
|---|---|
| 摄像头 / 处理单元写入 | 606 / 584 帧，0 错、0 丢；处理单元每个摄像头帧都处理到 |
| 显示两层 | 各约 60 帧/秒，坏行不增加（只有上电前 3 帧黑），两层 seq 差 0 |
| DDR 读延迟峰值 / 写延迟峰值 | 242 / 287 时钟 |
| 资源 | u_vid 0 DSP、59 块 Memory；全片 Memory 192/256、DSP 4；core_clk slack 3.2 ns |

Memory 去向：SoC 81、DDR 控制器 39、CSI RX 11、u_vid 59。旧帧缓冲已被综合裁掉（不占 Memory），
所以 Phase 4 删旧代码省不出 Memory；关掉 DMA 自检可省 14 块。每个 DMA 引擎 7 块是 130 位宽 FIFO 的下限（RAM 最宽 20 位）。

## 10. Phase 4：退役旧通路（2026-10-21）

用户确认 Phase 3 画面：左边颜色正确、右边反色、稳定正常。随后删除：`rtl/frame_buffer_V3/`、`rtl/debayer/`、
`rtl/display/{layer_fetch,frame_sync}.sv`、`rtl/video/`、`gamma_correction.v`、`axi2_pri_arb.v`，以及顶层的显示域
BLC / 白平衡 / gamma / 饱和度、`DBG_PATTERN`、旧采集探针和旧遥测分支。`raster_gen.sv` 移入 `rtl/vid/disp/`。
`vid_subsystem` 的旧帧缓冲端口改为通用外部主机端口 `ext_*`，接 ST 加速器（随 `ENABLE_ST_ACCEL` 启用）。

上板：XLR 29.5k → 28.6k（旧帧缓冲本已被综合裁掉，Memory 不变 192），遥测各项与 Phase 3 相同，
`board_smoke_test.py --vid` 的 `ok` 改为按当前遥测判定并通过。架构文档重写为 `docs/video_architecture.md`。

## 11. Sobel 占位（2026-10-21）

`proc_stub` 加 `PROC_SOBEL`：亮度 (R+2G+B)/4 → 3×3 Sobel → (|gx|+|gy|)/2 灰度；两行亮度缓冲（4 块 Memory），
两级弹性流水，输出 (x, y) 以输入 (x−2, y−1) 为中心。`tb_disp_split` 逐像素核对，`tb_proc` 核对随机反压下输出不变。
仿真首版在色带边界处边缘变成 4 像素宽、半强度：行缓冲里一行的两个像素顺序反了（非压缩数组字面量 `'{a, b}` 中 a 是元素 0）。
Efinity 不接受嵌套的 `'{default: '{default: ...}}`，复位改为循环。上板满负载 0 错 0 丢。
