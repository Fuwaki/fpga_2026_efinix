# 720p 改造排查记录

| 项 | 值 |
|---|---|
| 板卡 | Titanium Ti60F225 + SC431HAI (4-lane) + DDR3 |
| 起点 | `edd33d9`（1080p 裁切，画面正常） |
| 当前基线 | 1280×720 中心裁切，居中显示在 1080p 光栅内，画面正常 |
| 未完成 | 2×2 binning |
| 日期 | 2026-10-20 |

## 1. 结论

| 现象 | 根因 | 处理 |
|---|---|---|
| 黑屏，HDMI 锁定 | `frame_buffer_read.sv` 里 `LAYER_X/LAYER_Y` 重复声明，综合器丢弃了新声明（`VERI-2170/1329`），实际 `layer_x = h_active = 960`，窗口永远不命中 | 删除旧声明；`build_all.sh` 遇到这两条警告直接失败 |
| 定格、左右两份、摇晃 | 厂商 720p 表是 2-lane 的，PLL（`0x36EB/36EC/37FB/37FC`）在本板 4-lane 下只出 FS/FE 短包、没有行数据；DDR 从未被写，读侧显示的是上次运行的残留 | 改用 1080p 表为基表 |
| 块状错位、左侧异色竖条、曝光跳动 | binning 控制组 `0x3215/0x3220/0x5000/0x5900/0x5901` 本身（见 §3） | 基线不写这组寄存器 |

## 2. 已排除

- **FPGA 读写通路**：`DBG_PATTERN=1` 把像素换成逐帧变基址的计数器（保留传感器的 vs/hs/de），
  在 `layer_fetch` 入口和出口各校验一次：每帧 460800 字、连续无断点、无欠载、flush 时无残留，
  画面为逐帧滚动的渐变栅格。即没有丢字、没有错位、没有旧帧混入。
- **镜像**：数据手册 V1.1 表 2-11，`0x3221` 只有 mirror `[2:1]` 和 flip `[6:5]`。
  `config/sc431hai_720p_binning.md` 里“`0x3221=0x22` 开 binning”的说法不成立（0x22 只置了每对中的一位）。
- **lane 配置**：`0x3018/0x3019` 不写，用上电默认（4-lane），与 1080p 表一致。

## 3. binning 现状

在当前基线表上，开流前追加厂商 720p 表独有的 5 条：

```
0x3215=0x31  0x3220=0x01  0x5000=0x46  0x5900=0x01  0x5901=0x04
```

结果：1280×720 正常出流、画面变亮（说明确实在合并像素），但有固定在输出坐标上的块状错位和左侧异色竖条；
开关镜像时场景翻转而纹路不动。去掉这 5 条即恢复正常。FPGA 侧已验证无误（§2），所以问题在传感器这组寄存器。

数据手册 V1.1 没有记录 binning 寄存器。公开渠道没找到 4-lane 的 SC431HAI binning 表。

### 建议的下一步

1. 二分这 5 条：模拟侧 `0x3215/0x3220` 与数字侧 `0x5000/0x5900/0x5901` 分开试，判断错位来自哪一级。
2. 用传感器自带灰度渐变测试图（`0x4501` bit3）配合 binning，区分像素阵列读出与数字后处理。
3. 向思特威 FAE 要 4-lane 的 2×2 binning 配置。

## 4. 调试设施

| 开关 / 字段 | 位置 | 作用 |
|---|---|---|
| `DBG_PATTERN` | `fpga_src_top.v` | 0 = 摄像头；1 = 计数图样（读侧校验器生效）；2 = 几何图卡 |
| 采集探针 | `fpga_src_top.v` `cp_*` | CSI-2 RX 出口的 vs/hs/de 计数、每帧行数、每行拍数、错误标志（ST 关闭时占用 ST 遥测槽位） |
| `frame_pix_num` | 遥测字节 18[7:4]、24[7:4]、27 | 每帧采集拍数低 16 位；1280×720 = `0x8400`，1080p = `0xE900` |
| 读侧诊断 | `frame_buffer_read` `dbg_*` | 每帧欠载周期、flush 时 FIFO 残留、推入字数、计数图样校验 |

摄像头模式下 `board_smoke_test.py --json` 字段对应：
`cap_samples` = de 周期累计，`cap_tiles` = hs 累计，`commit_count` = vs 累计，
`last_x` = 行/帧，`last_y` = 拍/行，`last_commit_addr` = CSI 错误粘滞位，
`st_tiles` = `{欠载周期[31:16], 残留[11:0]}`。

## 5. 其他未决

- 帧率约 12–16 fps，低于 VTS 计算值；1080p 表本身也只有约 14 fps。
- `board_smoke_test.py` 的 `ok` 判定仍按 ST 开启时的条件写，ST 关闭时恒为 FAIL。
